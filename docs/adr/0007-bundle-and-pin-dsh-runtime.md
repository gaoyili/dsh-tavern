# ADR 0007：内置固定 DSH，独立交付，与上游升级节奏隔离

- 日期：2026-09-22
- 状态：已决定；各平台打包与迁移按此原则实施，不表示已经全部完成。
- 范围：桌面版（包括基于 DSH Desktop 的封装）、安卓版（包括基于 DSHA 的封装）、命令行版。

## 背景

酒馆依赖 DSH 的会话、历史、消息投影、工具和运行环境。跟随上游升级，会持续引入接口变化、旧存档迁移和浏览器兼容风险。用户获得的新能力未必足以抵消这些成本。

酒馆交付的是稳定可玩的应用。用户不承担选择 DSH 版本、匹配插件或修复宿主升级的责任。

## 决策

**DSH 是酒馆内置并锁定的基础组件，不是用户需要独立安装和更新的外部宿主。酒馆不跟随上游主流版本升级；上游发布不触发酒馆升级、适配或存档迁移。**

### 1. 所有发行方式独立

| 发行方式 | 交付要求 |
| --- | --- |
| 桌面版 | 提供酒馆自己的完整安装包。封装所需桌面外壳、固定 DSH 和酒馆组件；用户不必先安装官方 DSH Desktop。 |
| 安卓版 | 提供酒馆自己的 APK 和受控运行环境。即使复用 DSHA 实现，也不依赖用户另装或升级官方 DSHA。 |
| 命令行版 | 提供独立安装入口和私有运行时；不依赖全局 DSH、全局 Profile 或其更新。Node 等必要运行组件也属于发行依赖契约，不能随系统环境无约束漂移。 |

各平台使用独立应用标识、配置、数据目录、服务生命周期和更新入口。可以与官方 DSH Desktop、DSHA、全局 DSH 并存；它们的安装、升级和卸载不改变酒馆。端口冲突由酒馆明确处理，不能误连其他宿主。

以一次下载、安装即可使用为目标。必要的平台运行资源若无法随包交付，只能按发行清单下载精确版本并校验完整性，不能在首次启动时拉取上游最新版。

### 2. 固定完整的兼容组合

每个酒馆发行版本记录并冻结 DSH 核心、桌面/安卓外壳、Node、插件、传递依赖和必要运行资源的版本、来源与校验值。仅锁 DSH 顶层版本不算隔离完成。构建和安装使用确定的锁文件或制品，不依赖 `latest`、浮动版本或用户全局依赖。

最终 DSH 核心基线固定为 **0.1.5-rc.2**。v2.1 是最后一次 DSH 本体升级适配，此后不再升级 DSH 核心或为上游新版本做迁移。对应桌面外壳为 Desktop 2.0.13、安卓外壳为 DSHA 0.1.5-rc2；打包资源仍需按平台实际验收，不能由版本号推定可用。

系统 WebView 等仍由操作系统提供的组件，应明确最低能力和兼容范围，启动时检测并给出可操作的错误。固定 DSH 不等于固定 WebView；若以后内置网页内核，其更新与安全维护也由酒馆承担。

### 3. 用户只更新酒馆

生产包中不提供会独立升级内置 DSH、Desktop、DSHA 或依赖的上游更新通道。酒馆更新器只安装酒馆发布并验收的组合，不改变官方产品的配置和更新策略。

酒馆功能更新保持上述 DSH 核心基线。新功能在酒馆内实现；第三方插件若只支持更新的 DSH，选择兼容版本、局部适配或放弃接入，不以此推动核心升级。

### 4. 维护固定基线，不再升级本体

酒馆已深度改造 UI、提示词组装、消息渲染、历史管理和后台工具。核心升级会同时改变这些契约，引入接近重写的适配成本与旧存档风险。上游新增能力不足以成为整套升级的理由。

需要修复缺陷、安全问题或平台兼容问题时，在固定基线上维护范围明确、可测试的补丁；必要时回移单项上游修复，记录来源和影响，不以“修复”为由整体替换 DSH。外壳或系统 WebView 的必要维护，也不得偷偷升级内置核心。

不再创建常规 DSH 追新适配任务，不维护多版本兼容矩阵。新模型、工具或插件能力通过酒馆自己的接口接入；无法在固定基线上合理实现的需求，明确说明限制。接受固定版本的维护责任。

### 5. 数据独立，迁移可恢复

程序与用户数据分离。覆盖安装、更新和重装不得覆盖资源库、用户 Skill、配置及存档。

运行时变更涉及格式迁移时，先保存可校验的备份，在副本上验证，再发布新数据；保留迁移记录与原件。发布失败时恢复匹配的程序和数据，不能只降级二进制却继续读取已升级存档。升级后新增进度需保留副本，不能在回退中静默丢弃。

从官方宿主或其他酒馆安装导入数据是显式、单向复制流程，保留来源；禁止多个独立发行版共享可写存档目录。

### 6. 发布以用户路径验收

每次改变运行时组合，至少验证：

- 首次安装、一键启动、覆盖更新，以及与官方产品并存。
- 旧存档列表、打开、切换、刷新、重启后恢复。
- 正文生成、重新生成、回退、历史正文编辑与上下文一致性。
- 后台 Agent、MVU 初始化与结算、资源库、人物卡脚本与面板。
- 中断恢复、迁移失败保护，以及程序和数据的配套回退。
- 各目标平台的真实运行环境；安卓包含最低支持 WebView，不能用桌面浏览器结果替代。

自动化通过不代替实际安装和 UI 验收。未验收的平台或路径明确列出，不宣称完成。

## 实施边界

已有 Windows 安装包沿用此方向，逐项核对隔离是否完整。桌面其他平台、安卓和 CLI 按同一原则补齐；本文件不启动重打包、降级或用户数据迁移。

现有 Desktop/DSHA 插件安装方式属于过渡交付，不再作为长期架构目标。历史适配计划可用于理解已有实现，不再构成跟随上游升级的承诺；与本决策冲突时，以本决策为准。

Android 的主路线改为独立 APK（固定 `tavern` Profile，单 DSH 进程）；通过 DSHA 安装脚本的方式仅作兼容路线，适用于设备不满足 APK 要求或已在 DSHA 中积累配置的用户。两者数据独立，不自动迁移。

复用 DSH Desktop、DSHA 或其他组件进行封装时，落实相应许可证、再分发、署名和源码提供义务；独立产品身份不能冒用官方发行身份。
